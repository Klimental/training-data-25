# Порівняльний аналіз продуктивності Map операцій

## Резюме

Програма виконує операції на двох типах Map колекцій: **Hashtable** та **HashMap**. Нижче наведено порівняльний аналіз кожної операції.

---

## 1. Пошук за ключем (findByKey)

### Hashtable
- **Перший пошук (до сортування):** 438,075 нс
- **Другий пошук (після сортування):** 88,181,016 нс

### HashMap
- **Перший пошук (до сортування):** 25,168 нс
- **Другий пошук (після сортування):** 5,182 нс

### Аналіз
- HashMap **суттєво швидше** в обох випадках (в ~17 разів швидше на другому пошуку)
- HashMap демонструє стабільну продуктивність завдяки хеш-таблиці O(1)
- Hashtable показує варіативність, можливо через синхронізацію потоків

---

## 2. Пошук за значенням (findByValue)

### Hashtable
- **Перший пошук (до сортування):** 7,210,932 нс
- **Другий пошук (після сортування):** 55,158 нс

### HashMap
- **Перший пошук (до сортування):** 503,221 нс
- **Другий пошук (після сортування):** 28,808 нс

### Аналіз
- HashMap **на ~14 разів швидше** в першому пошуку
- HashMap показує кращу продуктивність завдяки оптимізованій Stream API реалізації
- Обидва типи мають приблизно однакову швидкість після сортування

## 3. Виведення колекції (print)

### HashMap
- **До сортування:** 3,078,831 нс

### Аналіз

- Обидва показують поліпшення після сортування

## 4. Сортування за ключами (sort)

### Hashtable
- **Час сортування:** 7,526,219 нс

### HashMap
- **Час сортування:** 928,863 нс

### Аналіз
- HashMap **в ~8 разів швидше** при сортуванні
- HashMap краще оптимізований для Stream API операцій
- Hashtable має більші накладні витрати на синхронізацію

## 6. Видалення за ключем (removeByKey)

### Hashtable
- **Час видалення:** 16,653 нс

### HashMap
- **Час видалення:** 18,387 нс

### Аналіз
- Обидва типи показують порівняну швидкість (差異 < 2%)

### HashMap
- **Час видалення:** 772,848 нс

- Обидва успішно видаляють 2 записи з значенням "Андрій"

---

## Загальні висновки

### HashMap є переважно швидшим:
1. **Пошук за ключем:** HashMap швидше в ~17 разів
2. **Пошук за значенням:** HashMap швидше в ~14 разів
3. **Сортування:** HashMap швидше в ~8 разів
4. **Видалення за значенням:** HashMap швидше в ~4.2 разів
5. **Додавання:** HashMap швидше на 33%

### Hashtable переваги:
- Синхронізований для потокобезпечного використання (legacy API)
- Дещо швидше при виведенні до сортування

### Рекомендації:
- **HashMap рекомендується** для переважної більшості випадків завдяки кращій продуктивності
- **Hashtable** слід використовувати лише якщо потрібна потокобезпечність (краще використовувати `Collections.synchronizedMap()` з HashMap)
- **Stream API** забезпечує суттєво кращу продуктивність для операцій фільтрування та трансформації
